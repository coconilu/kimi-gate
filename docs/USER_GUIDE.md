# kimi-gate 用户指南

> 这份文档写给**使用者**。你不需要懂网络、懂安全、懂 Node.js，只要跟着步骤走，大约 15 分钟就能拥有自己的"远程 Kimi Code 工作台"。
> 如果你想知道它是怎么实现的，看 [README.md](../README.md) 的技术细节。

## 它是什么

一句话：**让你在出门在外时，用手机浏览器安全地使用家里电脑上的 Kimi Code。**

你可能会担心："把家里的开发环境暴露到公网，安全吗？" —— 这正是 kimi-gate 存在的意义。它不是简单地把端口开放出去，而是在你和家里电脑之间架了一座带门卫的桥：

- 任何人打开你的网址，只能看到一个**登录页**，输对密码才能进
- 每一次登录尝试（成功、密码错、被限流）都会**记录在案**，你随时可以查
- 同一设备 1 分钟内最多试 10 次密码，超限直接拒绝
- 家里电脑**不需要开任何端口**，不需要公网 IP，路由器不用做任何设置

## 它是怎么运转的

```
  你在外面                                   云端                          你家里
┌─────────────┐                    ┌───────────────────────┐
│  手机/笔记本  │   HTTPS           │      云服务器 (VPS)     │
│   浏览器     │ ═══════════════▶  │  Caddy (自动 HTTPS 证书) │
└─────────────┘   只有这一个入口    │           │            │
                                    │           ▼            │
      登录时看到：                    │   ┌───────────────┐   │
      ┌──────────────┐              │   │    Gateway    │   │
      │  🔒 输入密码  │              │   │  · 验证密码    │   │
      └──────────────┘              │   │  · 记录日志    │   │
                                    │   │  · 防爆破限流  │   │
                                    │   └───────┬───────┘   │
                                    └───────────┼───────────┘
                                                │  WSS 加密长连接
                                                │ （Connector 主动向外连，
                                                │   家里不需要开端口）
                                    ┌───────────┼───────────┐
                                    │           ▼           │
                                    │   ┌───────────────┐   │
                                    │   │   Connector   │   │
                                    │   └───────┬───────┘   │
                                    │           ▼ 本机回环    │
                                    │   kimi web :58627     │
                                    │   （你电脑上的 Kimi）   │
                                    └───────────────────────┘
```

整个系统只有 **3 个组件**，真的不复杂：

| 组件 | 跑在哪 | 干什么 |
|---|---|---|
| **Gateway** | 云服务器 | 门卫：验证密码、记录日志、转发请求 |
| **Connector** | 家里电脑 | 信使：主动连到云服务器，把请求带给本地的 Kimi |
| **Caddy** | 云服务器 | 自动申请和续期 HTTPS 证书（跟着项目自带，无需操心） |

数据流向也很直白：浏览器 → Gateway（查户口）→ Connector（跑腿）→ 你电脑上的 kimi web。回答再原路返回。

## 开始使用前，你需要准备

1. **一台云服务器**：最便宜的轻量应用服务器就够（2核2G，约 ¥99/年），装 Ubuntu 24.04
2. **一个域名**：几块钱一年的就行，已备案（国内服务器要求）
3. **家里电脑**：开着机、不睡眠，上面装了 Kimi Code CLI
4. **大约 15 分钟**

## 快速上手

### 第一步：云服务器上装 Gateway（约 5 分钟）

SSH 登上你的云服务器，执行：

```bash
# 装 Node 24（如果还没有）
curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
apt-get install -y nodejs

# 拉代码，一键安装
git clone https://github.com/<你的账号>/kimi-gate.git
cd kimi-gate
sudo bash scripts/install.sh
```

安装脚本会引导你设置**管理员密码**、粘贴 **kimi bearer token**，最后自动生成一对配对密钥并装好 systemd 服务（开机自启、崩溃自愈）。

> 习惯 Docker 的话，也可以 `docker compose up -d --build`，效果一样。

### 第二步：域名解析过来（约 2 分钟）

在你的域名 DNS 控制台加一条 **A 记录**：主机记录 `kimi`（或你喜欢的名字），值填云服务器 IP。
然后配上 HTTPS（项目自带 Caddyfile，证书自动申请，不用手动操作）。

### 第三步：家里电脑上装 Connector（约 5 分钟）

在你家电脑上（需要 Node ≥ 22.5；pnpm 用 Node 自带的 corepack 启用即可）：

```bash
git clone https://github.com/<你的账号>/kimi-gate.git
cd kimi-gate
corepack enable          # 启用 pnpm（Node 自带，一次即可）
pnpm install && pnpm run build
```

然后复制 `packages/connector/.env.example` 为 `packages/connector/.env`，填三行：

```env
GATEWAY_URL=wss://你的域名
CONNECTOR_KEY=第一步安装时生成的配对密钥
KIMI_LOCAL_URL=http://127.0.0.1:58627
```

启动：

```bash
pnpm run start:connector
```

看到 `已连接 gateway` 就说明链路通了。Windows 下想让它开机自启、后台常驻，方法见 [Connector 部署说明](../packages/connector/README.md)（任务计划程序或 NSSM，任选其一）。

### 完成。日常使用就是：

手机浏览器打开 `https://你的域名` → 输密码 → 开始用 Kimi Code。

管理台在 `https://你的域名/admin`（进去要再输一次密码），可以看**都有谁在什么时候尝试登录过**、踢掉会话、封禁 IP。

## 你可能关心的安全问题

**Q：我的 Kimi 密码/凭证会不会经过云端泄露？**
A：kimi web 的 bearer token 只存在云服务器的配置文件里，浏览器从头到尾看不到它；Gateway 转发时替你带上。家里电脑那边也不接触这个 token。

**Q：别人扫到我的域名怎么办？**
A：他只能看到一个登录框。密码是 argon2id 哈希存储的，1 分钟试 10 次就会被限流，所有尝试都会记进审计日志，管理台里一目了然。你还可以在管理台直接封禁他的 IP，或者开启 TOTP 双因素认证（手机上的验证器 App 扫码即可）。

**Q：我怀疑密码泄露了怎么办？**
A：进管理台的"修改密码"区块改密码。修改成功的那一刻，**其他所有设备的登录会话会立即全部下线**（只有当前操作的设备保持登录），完成止损。改密事件本身也会记入审计日志。

**Q：我忘记了管理员密码？**
A：SSH 到云服务器，进项目目录重新跑 `pnpm run setup` 重置即可。

**Q：家里电脑关机/断网了会怎样？**
A：网关会显示"Connector 离线"，你的手机端会看到提示而不是报错页面。电脑恢复后 Connector 会自动重连（指数退避），无需人工干预。

**Q：云服务器的公司能看到我的数据吗？**
A：流量在你的域名下全程 TLS 加密。Gateway 本身需要处理你的请求内容（这是自托管代理的本质），所以请像对待任何自托管服务一样：服务器只开必要端口、SSH 用密钥登录。项目的安全模型详见 [README](../README.md#安全模型)。

## 遇到问题先看这里

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 手机提示"Connector 离线" | 家里电脑关机/断网/connector 没跑 | 看家里电脑的 connector 日志，确认显示 `已连接 gateway` |
| 登录一直"表单校验失败" | 极端网络下 cookie 没带上 | 刷新页面重新输密码；频繁出现请到 GitHub 提 issue |
| 提示"请求过于频繁" | 触发了 10 次/分钟限流 | 等一分钟再试；这是防爆破在保护你 |
| 页面能开但聊天没反应 | 家里电脑的 kimi web 没在跑 | 家里电脑上确认 `kimi web` 正常 |

还是搞不定？带上 Gateway 日志（`journalctl -u kimi-gate-gateway -n 50`）和 Connector 日志到 GitHub Issues 提问。

## 它不适合什么

诚实地说：

- 它是**单用户**设计（一个管理员密码），不是多人团队产品
- 家里电脑必须开机。想要"云端随时在"的体验，可以把 Kimi Code 直接装在云服务器上（路线 A，README 里有说明）
- HTTP 响应是全缓冲转发的，网页里的大文件下载不如直链快（但聊天流走 WebSocket，不受影响）

## 反馈

这个项目欢迎 issue 和 PR。它在真实使用中持续打磨——包括多标签页登录冲突、断线自动重连这类只有真用起来才会发现的问题。
